# Structured curricula

Configure the subject's stage, area or module, course, territory, and VET qualification in **Contexto**. **Currículo** inherits these fields and shows a read-only summary with an **Editar en Contexto** shortcut. Set only curriculum-specific options here: academic year, sequencing scope, curriculum model, and a module code when needed. New extraction requests resolve subject identity from the latest server-side Context data, even if a browser submits an older profile. Saved drafts and activated versions retain their original identifying snapshots; a visible notice reports differences from current Context. Primary cycle scope derives its cycle from the subject's course. Professional VET modules use learning outcomes and assessment criteria; general Basic VET areas use specific competences and criteria.

## Obtain and review a curriculum

The elements list uses the full available width. Open an element to consult or edit it in a modal, including its source, original quotation, hierarchy, and review status. **Añadir elemento** opens the same editor; choose its kind there. Closing the modal retains changes in the local draft; use **Guardar borrador** to persist them. Escape closes the editor and restores focus to its trigger. Configuration is collapsed under **Configuración del currículo**. Import, export, reload, draft discard, and preparation for a new search are grouped under **Más acciones** when applicable.

- **Buscar en fuentes oficiales** asks the configured curriculum agent to locate the applicable published regulations and extract sources, elements, and explicit normative relationships. The request includes the chosen curriculum profile and excludes the subject's private context, teaching style, and indexed teaching sources from the prompt. Agent instructions prohibit reading private subject documents. This is a prompt boundary, not a filesystem sandbox.
- **Crear borrador editable** starts manual editing or copies the active version into a draft.
- **Preparar nueva búsqueda** starts an empty draft using current Context identity, with editable academic year and curriculum scope, without altering the active version. An empty saved draft can also be used as the starting profile for extraction.
- **Importar JSON** accepts the same structured draft format as **Exportar JSON** and resets element, source, and completeness review flags. It does not automatically activate imported content.

Review elements with their original codes, exact normative text, parent competence or learning outcome, source, locator, and original excerpt. Teacher notes are separate from normative text. Additional links distinguish relationships expressly stated in regulations from teacher proposals. Source records include publication and applicability information, a URL or provided-document identity, and review notes.

Elements form two independent hierarchies: learning outcomes (or specific competences) contain assessment criteria; content/knowledge blocks contain individual content/knowledge elements and optional subblocks. The element list renders these relationships as an indented hierarchy, preserving sibling order. Search retains matching elements and their ancestors. Parent selectors offer only the appropriate element types and exclude the element itself and its descendants. Outcomes and competences require criteria; blocks require content or subblocks; content requires a block. Additional links express relationships between the two hierarchies without implying that a content block belongs to a learning outcome. Criterion codes can repeat under different outcomes. Unnumbered normative blocks and content keep empty official codes and stable technical IDs. The interface and agent context derive local hierarchical labels (1, 1.1, 1.2, etc.) from the full sibling order, even during filtering. Official codes take precedence. Local numbering is explicitly identified as organizational and never written into normative codes or historical snapshots. Agent context retains the hierarchy and version-scoped parent references.

Activation requires a complete identifying profile, assessment criteria, valid criterion parents, distinct element codes within their parent/type, valid references, no parent cycles, source provenance, excerpt/text agreement, individual review, and an explicit completeness review. Recognized official domains are checked over HTTPS. Provided normative documents require a filename. Domain checks and excerpt comparisons do **not** establish legal validity, verify that a URL actually contains a norm, or prove that extraction is complete. The teacher must compare the results with the original regulations, corrections, amendments, and applicable implementation dates.

Automatic extraction uses a dedicated system prompt without the note-writing conventions for images, solutions, or table captions. Its task identifies applicable norms, inventories source groups before transcription, transcribes literal text in the publication's language, and reconciles the final JSON against that inventory. The result must include `audit.status`, an `audit.inventory` entry for every kind/parent/source group with a source locator and expected count, and `audit.content` describing whether the norm publishes content. The server rejects inconsistent counts, uncovered groups, invalid hierarchy/provenance, missing dates, and absent published content before saving any draft, and asks the existing agent retry flow to correct the output. A `needsInformation` result surfaces concrete questions without committing a curriculum. Unpublished content needs an explicit source-backed explanation, which is copied to the source notes for teacher review. Unknown VET module codes can be resolved from the norm; known codes and subject identity are preserved. The raw output, including the self-reported audit, remains in the job's output file. Inventory reconciliation checks internal consistency; it does not independently verify source counts or certify legal completeness.

Choose **Revisar y activar** to review the whole curriculum once. The modal shows source observations that need checking. Explicitly confirm that you have reviewed the complete curriculum, sources, and applicability, then choose **Guardar y activar**. There is no need to mark every element or save separately first. Individual source/element review remains optional. Only an activated structured version reaches note planning, curriculum review, import diagnosis, exam generation and teaching programme authoring. Before activation, those flows have no curriculum context. The separate [teaching programme module](teaching-programmes.md) uses a pinned activated snapshot; territory-specific opposition rules are not included.

Global review submits a captured draft and its expected revision. The server validates the complete structure and provenance, records the explicit human confirmation across the elements/sources, and saves the activated version in one atomic revision. Invalid content, missing confirmation, and stale revisions leave existing drafts and versions unchanged. Activated snapshots record `reviewMethod="global"`; the original per-item API remains compatible. Source notes are retained. This confirmation is a teacher declaration, not automated verification of legal applicability or source completeness.

### Identified text with unresolved applicability

Extraction and legal applicability are separate checks. If the agent identifies the exact published curriculum text but cannot finish verifying its application to the requested academic year, it returns `audit.status="reviewRequired"`, concrete `audit.questions`, and the complete sources, elements, links, and inventory. The same structural, provenance, publication-date, and completeness checks still run. The server records the outstanding applicability questions in each source's notes and leaves sources, elements, and completeness unreviewed. The result is a pending draft, not an active or legally certified curriculum. Review those questions in **Fuentes** before confirming applicability and completeness. A transitional provision must be considered before treating a general repeal as removal of every curriculum annex.

`needsInformation` remains appropriate when the requested subject/module or its normative text cannot be identified; that response does not create a curriculum. `reviewRequired` cannot be used to bypass absent text, missing inventory groups, omitted criteria, or missing published content. A failed annual-instructions download alone need not discard a curriculum whose text has already been identified.

## Removing a source

In an editable draft, choose **Eliminar fuente del borrador** for any source, including the first source or the last remaining source. The dialog reports how many elements and relationships reference it. Choose another source to reassign those references, or leave them without a source pending completion. Deletion preserves normative text, hierarchy, relationships, locators, excerpts, and notes. Affected elements, the replacement source, and the completeness confirmation must be reviewed again. Preserved excerpts and locators must be checked against the replacement publication; reassignment does not verify provenance.

Save the draft to persist the change. Missing references or pending review block activation. Previously activated snapshots remain unchanged. Cancelling the dialog leaves the draft untouched.

## Extraction cost controls

Extraction uses a compact task and compact JSON. Literal normative text is generated once: when excerpt is omitted, the server copies text locally; explicitly supplied excerpts still undergo the same agreement check. Empty notes, review flags, and default official-source metadata are filled locally only for agent extraction. Manual JSON imports retain their strict schema. Inventory, hierarchy, provenance, publication dates, and applicability checks remain mandatory. Instructions prioritize direct official HTML or the relevant PDF pages, reuse already consulted sources, and avoid re-running broad searches during corrections. Reasoning effort is capped at medium (lower user settings remain lower), and curriculum postprocessing allows one automatic correction rather than the general two-correction limit. These controls reduce avoidable work; actual usage still depends on the source and model, and no live token-saving percentage is claimed.

## Persistence and agent context

Each subject stores one atomic `curriculum/state.json` envelope containing its schema version, optimistic revision, optional draft, active-version ID, immutable activated snapshots, and applied extraction receipts. Activated element references include both version and element IDs. Later edits create a draft; old versions are not rewritten. **Copiar a borrador** restores a historical snapshot for editing without changing the active version.

Mutations require the revision read by the caller. Concurrent or late writes receive HTTP 409 instead of overwriting newer work. Duplicate extraction receipts are idempotent. Corrupt structured state fails explicitly rather than silently falling back to a potentially stale document.

Structured state is the only curriculum source. `Almacen.curriculumPrompt()` renders the activated version as agent context, including version-scoped element references and provenance. Drafts are never used as teaching context. Obsolete `curriculo.md` files are ignored; there is no migration workflow, document editor, or text-based curriculum API. Existing files are not deleted automatically.

Unsaved form changes are recovered through tab-local `sessionStorage`, together with their original revision. A recovered stale draft still receives a conflict on save; export it before discarding or reloading. Browser storage is a convenience recovery mechanism, not a backup. Subject backups include the structured state through the existing backup mechanism.

## API

All paths are relative to `/api/asignaturas/:a/curriculo`:

| Method | Path | Request / result |
| --- | --- | --- |
| GET | `/` | Structured state and suggested profile |
| PUT | `/` | `{ draft, expectedRevision }` |
| DELETE | `/` | `{ expectedRevision }`; discard draft only |
| POST | `/activar` | `{ expectedRevision }` |
| POST | `/restaurar` | `{ versionId, expectedRevision }`; historical copy to draft |
| POST | `/buscar` | `{ profile, indicaciones? }`; queued agent job |

Types and deterministic checks live in `shared/curriculum.ts`; runtime parsing and atomic state operations live in `server/curriculumStore.ts`.

## Moving curriculum elements

Each tree row has a keyboard-accessible **Mover** action. Its dialog selects a compatible parent and a position before another sibling or at the end. Destination choices use the complete draft, including elements hidden by the current search. Moving a branch carries all descendants and preserves exact IDs, normative codes, text, source provenance and relationships. Descendants cannot become parents of their own ancestors. Criteria follow the captured general/VET model; knowledge stays under content blocks and descriptors under key competences.

Moves are local draft edits until explicitly saved, and never change an activated snapshot. Reordering retains individual review flags; changing the parent clears the moved elements own review flag and the global completeness acknowledgement. Save/reload retains both order and hierarchy, with existing revision conflict protection. Tests cover branch/sibling ordering, stage-compatible parents, cycles, invalid destinations, immutable data and durable storage with active snapshot preservation.

## Dragging branches and source dialogs

The tree move control is also a native desktop drag handle. Drop in the upper or lower quarter of another row to insert before or after it; drop in the centre to append under that element when its kind is compatible. A line marks insertion edges and an inset highlight marks nesting. The status region describes the current destination. Hovering over a valid nesting target expands its branch after 650 ms. The clicked handle retains the keyboard-accessible Move dialog.

Drop resolution uses the complete draft, including search-hidden descendants. It rejects self/descendant drops, incompatible parents and unchanged positions. Only a drag originating from this tree can trigger relocation; external file/text drops are ignored. All existing draft persistence, revision checks, reference retention and immutable active snapshot boundaries still apply.

Curriculum sources now use a compact list with **Añadir fuente**, **Modificar** and **Eliminar** actions. Creation and editing use a separate dialog with a local edit buffer; cancellation cannot leave an empty source or apply partial edits. Closing changed fields asks before discarding them. Applying updates the draft, and the main **Guardar borrador** action persists it. Existing source-removal replacement choices and linked-element review invalidation are retained. Sources in an active version can be modified by preparing draft changes without mutating the snapshot.
