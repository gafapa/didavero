# Teaching programmes

The subject-level **Programaciones** tab lists multiple named teaching programmes, alongside Notes (**Apuntes**) and Exams. **Nueva programación** opens a compact modal asking only for the title and purpose (classroom use or opposition). Creation saves a blank draft and opens that programme's workspace. Returning to the list allows another programme to be created without replacing earlier work. The subject tab displays the programme count.

Each programme has separate **Uso docente en el centro** and **Oposiciones** drafts, revisions, generation jobs and reviewed copies. Its authoring sections come exclusively from the researched outline; there is no preset index for any stage. Primary, secondary and VET profiles guide research and generation instructions. This is an authoring workflow, not a certified regional administrative format or a PROENS integration.

## Workflow

1. Activate the subject curriculum.
2. Open **Programaciones**, choose **Nueva programación**, name it and select the initial purpose. Enter course hours and describe the group and institution later in the editor, without student personal data.
3. Choose **Investigar** to research the structure before drafting. No course hours are required for research. The action uses the linked curriculum's stage, autonomous community, subject/module, course and academic year, the selected purpose, the subject context and audience, and that programme version's saved context. Unsaved programme edits are saved first. The existing researcher role performs a web-enabled job without indexed teaching files or unrelated documents. It is instructed to keep personal names and group/institution identifiers out of searches and the report, and to search using general educational terms. Research sees the teaching context for adaptation; this is not a guarantee of automatic personal-data anonymisation.
4. Read the ordered outline, documented requirements, context adaptations, source links/locators and pending questions in **Ver estructura y fuentes**. Partial useful findings are kept when applicability or a call is uncertain. **Volver a investigar** refreshes the report explicitly, reusing previous findings. Changes to the subject/group/programme context or supplied territorial/call requirements are detected locally using a context fingerprint; the UI warns when adaptation needs updating. The research prompt also uses supplied call/specialty details to narrow subsequent searches. Research does not overwrite units, prose or reviewed copies.
5. Research automatically supplies the programme's section titles, order, descriptions and source references. The UI adopts this structure into the editable draft; saving persists its research revision and section texts. Before research there are no programme sections and AI generation is unavailable. Add units manually or choose **Proponer con IA** after research and after entering the course hours. Generation reuses the saved research without repeating web searches and must retain the exact section definitions and order. It uses the linked curriculum, existing subject-context prompt conventions and relevant subject-source fragments when source access is permitted; it does not repeat normative extraction. Source tools, when configured, allow further targeted lookup. Sources belonging to individual Notes are excluded. Source-based prose and activity resources should identify their filename/page; teaching material does not replace researched normative requirements.
6. Edit units in a modal: sequence, hours, optional sessions, period, learning/professional situation and exact curriculum references. Each structured activity has its own tasks, objectives, evidence, assessment instrument, resources and curriculum assignments. AI assistance can propose the unit sequence or develop one unit; those proposals are previewed separately before explicit application. See [Curriculum-linked units and activities](programme-unit-planning.md) for stage differences, research sources and compatibility details. Edit each researched programme section in its own modal. **Contexto y requisitos (opcional)** keeps the planning context and supplied territorial/call requirements separate from the published index. Refreshed research retains authored text by stable section ID or an unambiguous unchanged title; removed authored sections move to **Textos anteriores sin asignar**, where they remain editable and are included as an appendix in Markdown. Older fixed-field prose is retained without restoring a preset index.
7. Use the grouped pending checklist to check hours, criterion and knowledge coverage, configured minimum unit counts and missing sections. These checks run locally without model calls.
8. Review the didactic decisions, then **Marcar como revisada** once. A protected copy remains available while subsequent edits continue in the draft.
9. Preview or export Word (DOCX), PDF, LibreOffice (ODT) or Markdown, including unsaved local edits. Choose the format beside **Exportar**. The reviewed copy has a separate download using the same format selection. Administrative-platform exports remain outside this module.

## Persistence and provenance

Each programme is stored under `programaciones/<project-id>/` beneath the subject directory. `project.json` records its identity, initial purpose and pinned curriculum; `state.json` holds the classroom version and `opposition.json` the opposition version. Project IDs and purpose are validated at the API and persistence boundaries. Full-file writes are atomic; read/modify/write operations are serialized across store instances and require an exact optimistic revision. Delayed model results cannot overwrite a newer draft. Job receipts make successful post-processing idempotent. Invalid or corrupt state fails closed and remains on disk.

The programme pins an immutable curriculum version, including scoped element IDs. New curriculum activations do not remap existing programmes. Initial project creation requires the active version; both purposes of an existing project continue using its original snapshot, even if the second purpose is first edited after a new curriculum activation. Moving an existing programme to another curriculum version remains a future feature; a new programme can be created for another year or group.

Research is stored separately in `research-classroom.json` or `research-opposition.json` with its own revision, job receipts, captured curriculum/profile and context fingerprint. Atomic revision-checked acceptance rejects stale reports and is idempotent across retries. Invalid output leaves earlier reports intact; damaged report storage fails closed. Structural validation requires official-source references for mandatory sections and requirements and rejects unsafe URLs, unknown references and unsupported ready states. Official source excerpts are independently matched against safely retrieved text when available. The server records matched, not-matched or unavailable status; model-supplied verification flags are discarded. A literal match establishes quotation presence, never current legal applicability. Missing matches retain a pending question. No additional model review loop is triggered.

Model output is parsed and validated before persistence: bounded arrays and strings, finite non-negative hours, unique unit IDs, correct criterion/content kinds and membership of the pinned curriculum. The captured total course hours must be preserved. Coverage and completeness checks remain visible for teacher review rather than triggering additional model review rounds. Generated text is always a draft, never an automatic teacher approval.

Programme sections are stored in `researchedSections` with their text and the adopted `researchRevision`; removed authored sections are preserved in `archivedSections`. Model post-processing rejects changes to the researched section count/order/definitions, the captured research revision, or archived text. Research refreshed during a generation job invalidates that job's structural snapshot without overwriting the saved draft. Export and completeness checks use the adopted sections rather than a hard-coded stage template. Historical reviewed copies retain their original structure and prose. New reviewed copies also capture the exact research report and its source locators under the same project lock. Review rejects a changed research revision or outline; old snapshots without an embedded report remain readable and never borrow a newer report.

Unsaved changes are retained in session storage across tab changes when available. Edits made while a save request is pending remain in the local draft, using the newly committed base revision; older load responses cannot replace them. A request to research or generate stops if additional unsaved edits arrive during its preliminary save. On revision conflicts, local edits remain visible and can be exported before reloading. The UI does not silently merge conflicting teacher and model changes. The reviewed snapshot is replaced only after another explicit successful review.

Default exports include literal curriculum text for selected references, teacher planning inputs, source notes and matching research provenance, including unresolved applicability observations. Optional presentation settings can publish the body without evidence appendices; stored originals remain unchanged. Compact references show complete ancestor code paths in units and activities and include literal references once in the optional appendix. Draft export does not save or review the draft. Binary conversion uses a unique temporary directory, Pandoc sandboxing, disabled raw markup and a trusted filter replacing embedded images with captions; it cannot fetch image URLs or include arbitrary local images. PDF compilation is confined to that temporary directory. Subject reference templates are reused for DOCX/ODT. Passing structural checks and teacher review do not independently establish normative completeness or legal applicability.

## Stage and territorial scope

Research considers learning situations and family/tutorial coordination for Primary, subject-level competency work for Secondary, and professional tasks, cycle coordination and workplace learning for VET. It determines which sections actually belong in the specific programme instead of inserting these topics as a universal index. Criteria retain their original competence/learning-outcome parent and content retains its block parent. Selection research considers the relevant call requirements, without inventing centre/company allocations or formal limits.

The territorial profile comes from the curriculum snapshot. The research job investigates territorial and call-specific rules using current official sources, retaining explicit uncertainties instead of substituting another territory/year. There are no certified regional packs and no hard-coded universal page limit, unit count or defence duration. The optional Presentation modal configures A4, installed font, size, line spacing, margins, minimum units and a maximum PDF page count. PDF limits are checked after actual layout and include every exported page. An optional generated table of contents replaces a dedicated authored index section only in binary exports; PDF page references are computed, while Office fields may need refreshing in the receiving editor. Word and LibreOffice can paginate differently. These controls do not certify administrative acceptance or infer legal rules from prose.

The distinction is supported by the official primary and secondary frameworks ([RD 157/2022](https://www.boe.es/eli/es/rd/2022/03/01/157/con), [RD 217/2022](https://www.boe.es/buscar/act.php?id=BOE-A-2022-4975)), the learning-outcome assessment framework for [VET, RD 659/2023](https://www.boe.es/buscar/act.php?id=BOE-A-2023-16889), and the separate general/VET teaching-programme rubrics in the [Galicia 2026 selection call](https://www.edu.xunta.gal/portal/sites/web/files/orde_18_de_febreiro_de_2026_.pdf), annexes VI and VII. These references informed the authoring distinction; they do not establish applicability to any other year, territory or specialty.

## Validation

`tests/teaching-programme.test.ts` covers input validation, invalid references and numeric values, review snapshots, optimistic and concurrent writes, pinned curriculum versions, damaged storage, synthetic model output acceptance and late results, and HTTP save/review/export behavior. Tests use isolated fictional curricula without live model calls or private teaching material.

`tests/programme-research.test.ts` covers provenance validation, partial results, concurrent/stale and duplicate results, corruption, all supported stage identifiers, autonomous-community and module specificity, selected planning-context inclusion, exclusion of unrelated private files/style/project titles, context-change detection, web permissions, per-purpose isolation, and reuse in generation. Model outputs are synthetic; these tests do not qualify live research quality or legal applicability.

## Deleting and restoring programmes

Each programme card has an **Eliminar** action. Confirmation moves the complete project (both purposes, research, unit proposals and reviewed copies) to the application trash. Restore it through **Inicio → Papelera**; an existing destination is never overwritten. Active or queued programme jobs must finish or be cancelled before deletion. Project writes and moves are serialized so an older open editor or delayed request cannot recreate a deleted project.

## Public evidence and live qualification

Research can prepare a bounded, 24-hour cache of admitted public curricular PDFs and discover the current Galicia PROENS manual from its official landing page. Agents receive page-labelled local text and must search it selectively rather than read entire manuals. Partial extraction and inaccessible sources remain explicit. Downloads retain the existing public-network checks, timeouts and size limits; a private DNS result is not bypassed. Curriculum source applicability notes are included once in generation context.

AI results normalize only exact version-qualified IDs belonging to the captured curriculum and losslessly convert plain string arrays in activity objectives/resources to text. Unknown IDs and foreign version prefixes still fail. All three programme jobs receive absolute output paths. A missing result file permits one focused retry to write the existing result; it does not authorize repeated research. Validation errors replace misleading model success messages while preserving the original response in job history.

The opt-in scripts in `scripts/validate-programmes-live.mts`, `scripts/recover-programme-live.mts` and `scripts/continue-programme-opposition-live.mts` retain actual model receipts and isolate fictional teaching contexts from the configured user workspace. They are not part of ordinary automated tests. See the [2026-10-19 live validation report](../output/programme-live-validation-2026-10-19/README.md) for observed defects, fixes, stage coverage, export evidence and unresolved qualification limits.
